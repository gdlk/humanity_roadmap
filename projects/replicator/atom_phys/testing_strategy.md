# Стратегия тестирования AtomPhys

## 1. Уровни тестирования

### 1.1. Unit Tests (C++)
*   **Цель:** Проверка корректности отдельных функций (расчет сил, интегрирование).
*   **Инструмент:** Google Test (GTest).
*   **Примеры:**
    *   Проверка закона сохранения энергии для двух частиц с потенциалом LJ.
    *   Проверка периодических граничных условий (частица, вылетающая справа, появляется слева).

### 1.2. Integration Tests (Python)
*   **Цель:** Проверка взаимодействия модулей через Python API.
*   **Инструмент:** PyTest.
*   **Сценарии:**
    *   Запуск симуляции на 100 шагов и проверка отсутствия NaN в координатах.
    *   Сравнение траектории с эталонной (Golden Master).

### 1.3. Validation (Научная точность)
*   **Цель:** Подтверждение физической корректности.
*   **Методика:** Сравнение результатов AtomPhys с проверенными пакетами (LAMMPS, GROMACS).
*   **Бенчмарки:**
    *   **Argon Gas:** Радиальная функция распределения (RDF) и коэффициент диффузии.
    *   **Water (SPC/E):** Плотность и диэлектрическая проницаемость.

## 2. Performance Benchmarking

### 2.1. Метрики
*   **ns/day:** Наносекунд симуляции в день реального времени.
*   **Atom-steps/second:** Количество обновлений атомов в секунду.

### 2.2. Сценарии нагрузки
1.  **Tiny:** 1,000 атомов (отладка).
2.  **Medium:** 100,000 атомов (типичная нано-деталь).
3.  **Large:** 1,000,000+ атомов (стресс-тест памяти и шины данных).

## 3. CI/CD Pipeline

1.  **Build:** Компиляция C++ кода (GCC/Clang/MSVC).
2.  **Unit Tests:** Запуск GTest.
3.  **Lint:** Clang-Tidy, Pylint.
4.  **Benchmarks:** Запуск на выделенном раннере, сравнение с предыдущим коммитом (регрессионное тестирование производительности).
